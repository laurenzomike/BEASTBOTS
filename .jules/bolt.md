## 2024-05-20 - React Array Computations & Firestore N+1
**Learning:** In React applications with frequent state updates (like polling intervals or complex UI components), using `.filter()` or `.map()` directly in the render body or derived state without `useMemo` causes severe CPU waste because those O(N) operations execute on every render tick. Compounding this, nested operations inside `.filter()`, such as `.toLowerCase()`, redundantly recalculate the same string values thousands of times. On the backend/data side, performing sequential database operations (like Firebase `getDocs()`) inside a loop leads to N+1 network requests, blocking the initialization flow.
**Action:** Always wrap derived collections (filtered arrays, sorted arrays) in a `useMemo` block. Extract invariant operations (like standardizing search queries) outside of the loop iterator to prevent O(N) recalculations. For database aggregations, fetch the full collection in a single batch query up-front, map the identifiers to a Javascript `Set`, and perform lookups in-memory with O(1) complexity.
