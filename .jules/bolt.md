## 2024-05-07 - [O(N*M) Render Bottleneck]
**Learning:** Found multiple instances where React components iterate over arrays (like `.map`) and perform O(M) searches (`.find()`) on another array inside each iteration. This causes O(N*M) rendering complexity which can severely block the main thread on large lists (like fleet grids parsing global activity logs). Also found expensive array sorts doing multiple `.findIndex` passes.
**Action:** When pairing arrays or computing derived state in React components, first consolidate the O(M) search array into an O(1) Lookup `Map` memoized via `React.useMemo`. Iterate forwards and use `if (!map.has(key)) map.set(key, value)` to preserve the "find first match" logic of `.find()`. In standard logic (like sorting), precompute index maps instead of recalculating index matching continuously.
